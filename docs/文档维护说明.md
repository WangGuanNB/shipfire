# 文档维护说明

> 本文档面向**人类维护者**与**各类 AI 工具**（Cursor、Claude、ChatGPT、Codex 等）。  
> 不绑定任何特定 IDE；按下方规则读写即可。

---

## 一、文档结构

```text
README.md                 ← 根入口（指向 docs/）
docs/
├── 产品说明.md           ← 产品总览 + 版本索引（常看）
├── 文档维护说明.md       ← 本文件
├── 版本0-早期访问.md     ← 各版本详情（按版本拆分）
├── 版本1-有限免费生成.md
├── 落地页说明.md         ← 落地页 / SEO 模块专项
└── 支付集成指南.md       ← 支付技术专项
```

**规则：所有 `.md` 文档统一放在 `docs/` 一层；根目录只保留 `README.md`。**

## 二、AI 阅读顺序

处理**产品方向、升级、版本规划**类任务时，按顺序阅读：

```text
1. README.md
2. docs/产品说明.md          → 确认当前在哪个版本
3. docs/版本X-xxx.md         → 读「执行中」那一版的阶段详情
4. docs/文档维护说明.md      → 若要改文档，先读本文件第三节
```

处理**写落地页、改首页 JSON、SEO 模块**时，额外阅读：

```text
5. docs/落地页说明.md
6. launch.yaml / my-page-build-factory.yaml（站点事实，非 MD）
```

处理**支付集成**时，额外阅读：

```text
5. docs/支付集成指南.md
```

### 通用开场话术（复制到任意 AI）

```text
请先阅读以下文件，再处理我的需求：
1. README.md
2. docs/产品说明.md
3. 产品说明里「执行中」对应的版本 MD
4. docs/文档维护说明.md

我的需求：……
```

若涉及落地页，追加：`docs/落地页说明.md`

## 三、什么时候改哪个文件

| 情况 | 怎么做 |
|------|--------|
| 产品定位、目标用户变了 | 改 `产品说明.md` |
| 当前版本里加一个小功能 / 小优化 | 改当前 `版本X-xxx.md`（加阶段或更新阶段状态） |
| 要开始一个新大版本 | **新建** `版本N-名称.md`，并在 `产品说明.md` 版本表加一行 |
| 某阶段完工 | 在该版本 MD 里把阶段标为 **已完成** |
| 整个版本验收通过 | 版本 MD 顶部标 **已完成**；`产品说明.md` 版本表同步；下一版本改为 **执行中** |
| 临时想法、还没拍板 | 写在当前版本 MD 末尾 **「待评估」** 小节，不要新建文件 |
| 写/改落地页模块 | 只改 JSON 与代码；模块设计原则参考 `落地页说明.md` |
| 支付逻辑变更 | 改代码 + 更新 `支付集成指南.md` |

### 版本 MD 命名规范

```text
版本{数字}-{简短中文主题}.md

示例：
  版本0-早期访问.md
  版本1-有限免费生成.md
```

## 四、禁止事项（AI 须遵守）

1. **不要修改「已完成」版本 MD 里的历史内容**（除非用户明确要求勘误）。
2. **不要在 `产品说明.md` 和版本 MD 里重复大段相同内容**——总览放产品说明，细节放版本 MD。
3. **不要新建子目录**——所有 MD 保持在 `docs/` 一层。
4. **不要未经用户确认**，把「待评估」里的想法改成「执行中」或直接写进路线图当作已定案。
5. **不要把产品路线图写进 `落地页说明.md`**——那是页面模块专项，不是产品版本文档。
6. **更新文档后**，若「当前阶段整体状态」变了，同步改 `产品说明.md` 的「当前版本」小节。

## 五、维护者日常习惯

**有个新想法时：**

- 还没想清楚 → 先不写，或记在版本 MD「待评估」一行
- 想清楚了，未拍板 → 写入当前版本 MD「待评估」列表
- 已拍板，小改动 → 在当前版本 MD 加/改一个阶段
- 已拍板，新大版本 → 新建版本 MD + 更新产品说明版本表

**每次发版或里程碑完成后（约 1 分钟）：**

1. 对应阶段 → **已完成**
2. `产品说明.md` 的「当前版本」是否仍准确
3. 若整个版本完成 → 版本状态改 **已完成**，下一版本改 **执行中**

## 六、与 Skills / 工厂工具的关系

- `my-page-build-factory` Skills 写落地页时，会查找项目内的落地页模块说明。
- 本项目路径为 **`docs/落地页说明.md`**（已从根目录迁入）。
- 调用 Skills 时，建议在提示中显式 `@docs/落地页说明.md`，避免仍找根目录旧路径。
- 站点事实（域名、关键词、路由）以 `launch.yaml`、`my-page-build-factory.yaml` 为准，不在产品版本 MD 里重复维护双份。

---

## 七、README.md 的职责

根目录 `README.md` 只做两件事：

1. 简短介绍项目 / 快速启动（保留模板说明）
2. **指向 `docs/`** 的产品文档索引

不要在 README 里写长篇产品规划——规划一律在 `docs/产品说明.md` 及版本 MD 中维护。
